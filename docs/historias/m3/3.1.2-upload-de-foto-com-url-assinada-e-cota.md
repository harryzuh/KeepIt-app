# 3.1.2 — Upload de foto por URL assinada, formatos, tamanho e cota do plano

**Módulo:** M3 (Fotos) · **Projeto Linear:** 3.1.2, 3.1.5 · **Prioridade:** Importante · **Depende de:** 3.0, 7.0
**UCs:** UC021 · **RF:** RF03, RF05, RF39 · **RNF:** RNF08, RNF09, RNF11, RNF19, RNF31
**Telas:** 08 Adicionar produto (bloco de fotos e barra de armazenamento)
**API:** `POST /produtos/fotos/upload-url` · **Erros:** 401, 403 `SEM_PERMISSAO`, 409 `COTA_EXCEDIDA`, 422 `ARQUIVO_INVALIDO`, 422 `LIMITE_FOTOS` (proposto), 429
**Camadas:** Back-end → Front-end · DevOps (S3) · QA · AppSec

## História
**Como** ADMIN ou EDITOR, **quero** anexar até 3 fotos ao produto, enviadas direto do navegador, **para** registrar como o item é sem sobrecarregar a API e sem estourar o espaço do meu plano.

## Critérios de aceite
1. **Dado** a tela 08, **quando** escolho uma imagem JPEG ou PNG de até 5 MB, **então** o front pede `POST /produtos/fotos/upload-url` (tipo e tamanho), recebe uma URL assinada válida por 5 minutos e a chave do objeto, envia o arquivo direto ao S3 e mostra a miniatura com opção de remover.
2. **Dado** o pedido de URL, **quando** o tipo declarado não é `image/jpeg` ou `image/png`, ou o tamanho é maior que 5 MB (5 242 880 bytes) ou menor ou igual a zero, **então** 422 `ARQUIVO_INVALIDO` com mensagem clara ("Use imagem JPEG ou PNG de até 5 MB") e nenhuma URL é emitida (RNF08, RNF09).
3. **Dado** que o arquivo só tem a extensão `.jpg` ou `.png`, mas o conteúdo real é outro (ex.: PDF, GIF, executável renomeado), **então** ele é recusado: o tipo real é conferido pelos primeiros bytes (assinatura JPEG `FF D8 FF`, PNG `89 50 4E 47 0D 0A 1A 0A`) no front (aviso imediato) e, de forma definitiva, na API ao salvar o produto (3.1), com 422 `ARQUIVO_INVALIDO`; o objeto inválido é apagado do S3.
4. **Dado** que o tamanho real do objeto enviado é diferente do declarado ou maior que 5 MB, **então** a API recusa ao confirmar (3.1) com 422 `ARQUIVO_INVALIDO`; a URL assinada limita o tamanho aceito quando o S3 suportar (Q3).
5. **Dado** que o produto já tem 3 fotos (contando as já salvas e as recém-enviadas), **então** o front desabilita "Adicionar foto" e a API recusa o pedido ou a confirmação com 422 `LIMITE_FOTOS` (proposto).
6. **Dado** o espaço usado + o tamanho da foto maior que o limite do plano (`exigirCotaParaEnvio`), **então** 409 `COTA_EXCEDIDA`, nenhuma URL emitida, a tela explica "Espaço do plano esgotado" e oferece o link para os Planos (UC020, exceção 2); no plano ADMIN o link leva à tela 13, para os demais papéis também (tela 13 é visível a todos).
7. **Dado** a tela 08, **então** exibe o uso de armazenamento da Casa (usado, limite e barra) com dados do `GET /me`, atualizado após salvar (RF39); o indicador completo do Início é do M4.
8. **Dado** a URL assinada, **então** vale por 5 minutos, é de uso único para uma chave gerada pelo servidor (nome do arquivo escolhido pelo cliente nunca vira chave) e fica escopada à Casa do usuário (prefixo da Casa na chave).
9. **Dado** que a URL expirou antes do envio, **então** o front pede outra automaticamente uma vez e, se falhar, mostra erro com "Tentar de novo" sem perder os demais dados do formulário.
10. **Dado** queda de rede ou erro do S3 no envio, **então** a miniatura mostra o erro e permite repetir ou remover; o botão Salvar fica bloqueado enquanto houver envio em andamento (RNF24).
11. **Dado** matriz de permissões, **então** ADMIN e EDITOR 200; LEITOR 403 `SEM_PERMISSAO`; sem token 401; rate limit por usuário (429) para impedir emissão em massa de URLs.
12. **Dado** cada miniatura, **então** tem `alt` descritivo e botão "Remover foto" com rótulo (RNF19).
13. **Dado** fotos enviadas que nunca foram vinculadas a um produto (usuário desistiu ou fechou a tela), **então** tratadas conforme a decisão do Arquiteto (Q4: limpeza de órfãs) e nunca contam na cota depois de limpas.

## Regras de negócio
- A cota (RF39) é a soma de `Foto.tamanhoBytes` da Casa; o serviço de plano é o único ponto da regra.
- Duas fotos simultâneas não podem, juntas, passar do limite (verificação repetida de forma segura na confirmação, em 3.1).
- A API é a autoridade sobre tipo e tamanho; a conferência do front é conveniência.
