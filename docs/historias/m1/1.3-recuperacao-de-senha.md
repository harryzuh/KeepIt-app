# 1.3 — Recuperação de senha por código

**Módulo:** M1 · **Projeto Linear:** 1.3, 1.3.1 · **Prioridade:** Essencial · **Depende de:** 1.0, 1.1, serviço de e-mail
**UCs:** UC006, UC007, UC009 · **RF:** RF17 · **RNF:** RNF02, RNF04, RNF11, RNF14, RNF15, RNF24
**Telas:** 02 Entrar (link) → 04 Recuperar senha (e-mail, depois código) → 18 Nova senha → 02
**API:** `POST /auth/recuperar-senha` (404 `CONTA_NAO_ENCONTRADA`, 429) · `POST /auth/redefinir-senha` (400 `CODIGO_INVALIDO`)
**Camadas:** Back-end (inclui e-mail e `CodigoVerificacao`) · Front-end · QA · AppSec

## História
**Como** usuário que esqueceu a senha, **quero** receber um código no meu e-mail e definir uma nova senha **para** recuperar o acesso à conta.

## Critérios de aceite
**Solicitar código (UC006, tela 04, etapa 1)**
1. **Dado** um e-mail cadastrado, **quando** clico em Recuperar, **então** é gerado um código de 6 dígitos (apenas o hash é guardado, finalidade `RECUPERAR_SENHA`), válido por 15 minutos, e enviado por e-mail; a tela passa à etapa do código.
2. **Dado** um e-mail não cadastrado, **então** a API responde 404 `CONTA_NAO_ENCONTRADA` e o front informa "Não encontramos uma conta com este e-mail" (comportamento previsto no UC006; riscos de enumeração tratados por rate limit e sinalizados ao AppSec).
3. **Dado** e-mail vazio ou inválido, **então** erro de validação no campo.
4. **Dado** que solicito novo código, **então** os códigos anteriores ainda não usados daquele usuário deixam de valer e apenas o mais recente é aceito (fluxo alternativo do UC007).
5. **Dado** a conta com exclusão solicitada, **então** não é enviado código (tratar como conta não encontrada).

**Validar código e redefinir (UC007, UC009, telas 04 etapa 2 e 18)**
6. **Dado** o código correto, não usado e dentro de 15 minutos, **quando** informo a nova senha (8+ caracteres) e a confirmação igual, **então** a senha é trocada (novo hash bcrypt), o código é marcado como usado e **todas as sessões ativas daquele usuário são invalidadas**.
7. **Dado** o fluxo concluído, **então** sou levado à tela 02 com a mensagem "Senha alterada. Entre com a nova senha" — sem login automático.
8. **Dado** código errado, expirado ou já usado, **então** a API responde 400 `CODIGO_INVALIDO`, o front mostra "Código inválido ou expirado" e oferece **Reenviar código**; a senha **não** é alterada.
9. **Dado** senhas diferentes ou com menos de 8 caracteres, **então** erro em tempo real no front e recusa na API (422).
10. **Dado** a tela 04, **quando** clico em Voltar ao login, **então** a recuperação é cancelada sem alterar a conta (fluxo alternativo do UC006).
11. **Dado** várias solicitações de código ou tentativas de código em sequência, **então** a API responde 429 (RNF14).
12. **Dado** o e-mail enviado em desenvolvimento, **então** ele é visível no Mailpit, contendo o código e o prazo de 15 minutos, sem link com token.

## Regras de negócio
- Código: 6 dígitos numéricos, aleatório criptograficamente seguro, **válido por 15 minutos**, uso único, só o hash é persistido.
- Cada usuário tem no máximo um código `RECUPERAR_SENHA` válido por vez.
- A tela 04 tem duas etapas (e-mail → código); a tela 18 define a nova senha. O código é conferido de forma definitiva em `/auth/redefinir-senha` (e-mail + código + nova senha); a etapa intermediária do front guarda e-mail e código em memória (decisão do PO; o Arquiteto pode propor endpoint de pré-validação sem consumir o código).
- Política de senha: mínimo 8 caracteres (RNF15).
- Redefinir senha **não** autentica o usuário.
