# 1.4 — Encerrar sessão (logout)

**Módulo:** M1 · **Projeto Linear:** 1.4, 8.4 (mesma funcionalidade; 8.4 é o ponto de entrada na tela Conta) · **Prioridade:** Média · **Depende de:** 1.0, 1.1, 8.1
**UCs:** UC012 · **RF:** RF21 · **RNF:** RNF01, RNF04
**Telas:** 16 Conta → 01 Boas-vindas
**API:** `POST /auth/logout`
**Camadas:** Back-end · Front-end · QA

## História
**Como** usuário logado (qualquer papel), **quero** encerrar minha sessão **para** que ninguém mais use minha conta no dispositivo.

## Critérios de aceite
1. **Dado** que estou na tela 16, **quando** clico em Encerrar sessão, **então** vejo uma confirmação.
2. **Dado** a confirmação, **quando** confirmo, **então** o token é descartado no navegador, o cache de dados (TanStack Query) é limpo, a API registra o encerramento e sou levado à tela 01.
3. **Dado** a confirmação, **quando** cancelo, **então** a sessão permanece ativa e continuo na tela 16 (fluxo alternativo).
4. **Dado** que a sessão foi encerrada, **quando** uso o botão Voltar do navegador, **então** nenhuma tela protegida exibe dados (rota protegida redireciona para 02).
5. **Dado** uma falha ao encerrar (ex.: API indisponível), **então** o front informa o erro e **mantém** o usuário na tela 16 (fluxo de exceção do UC012) — o descarte local do token só ocorre quando o encerramento for bem-sucedido, ou o usuário pode tentar novamente.
6. **Dado** um visitante sem token, **quando** chama `POST /auth/logout`, **então** recebe 401 (somente usuário autenticado encerra a própria sessão).
7. **Dado** que existe a tela 16 para LEITOR, EDITOR e ADMIN, **então** a opção está disponível para os três papéis.

## Regras de negócio
- Somente o usuário autenticado encerra a própria sessão.
- Mecanismo de invalidação do token no servidor depende da decisão do Arquiteto (ver decisões do PO no STATUS); mínimo: o token é descartado no cliente e deixa de ser aceito conforme o mecanismo definido.
