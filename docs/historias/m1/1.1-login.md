# 1.1 — Login

**Módulo:** M1 · **Projeto Linear:** 1.1, 1.1.1, 1.1.2, 1.1.3 · **Prioridade:** Essencial · **Depende de:** 1.0, 1.2
**UCs:** UC004, UC005 · **RF:** RF01 · **RNF:** RNF01, RNF02, RNF04, RNF11, RNF14, RNF24, RNF25, RNF19
**Telas:** 02 Entrar → 05 Início
**API:** `POST /auth/login` · **Erros:** 401 `CREDENCIAIS_INVALIDAS`, 422, 429 `MUITAS_TENTATIVAS`
**Camadas:** Back-end · Front-end · QA · AppSec

## História
**Como** usuário cadastrado, **quero** entrar com meu e-mail e senha **para** acessar o inventário da minha Casa.

## Critérios de aceite
1. **Dado** e-mail e senha corretos de uma conta ativa, **quando** clico em Entrar, **então** recebo um token JWT, sou levado à tela 05 e a sessão persiste ao recarregar a página até o token expirar.
2. **Dado** e-mail inexistente **ou** senha errada, **então** a API responde 401 `CREDENCIAIS_INVALIDAS` com a **mesma** resposta nos dois casos, e o front mostra uma mensagem genérica ("E-mail ou senha inválidos") mantendo-me na tela 02 e preservando o e-mail digitado.
3. **Dado** e-mail vazio, com formato inválido ou senha vazia, **então** o front acusa o erro no campo antes de chamar a API; a API também valida (422).
4. **Dado** uma conta com exclusão solicitada (`exclusaoSolicitadaEm` preenchido), **quando** tento entrar, **então** o login é recusado (mesma resposta genérica de credenciais inválidas).
5. **Dado** várias tentativas de login falhas em sequência do mesmo IP/e-mail, **então** a API responde 429 `MUITAS_TENTATIVAS` e o front exibe "Muitas tentativas. Tente novamente em alguns minutos".
6. **Dado** a tela 02, **quando** clico em "Esqueci minha senha", **então** vou à tela 04 (história 1.3); **quando** clico em "Criar conta", vou à tela 03.
7. **Dado** que digito a senha, **então** o campo oculta os caracteres e há alternância mostrar/ocultar com rótulo acessível (RNF25, RNF19).
8. **Dado** o login bem-sucedido, **então** a resposta não contém hash de senha nem dados de outros usuários.
9. **Dado** falta de conexão, **então** aparece a mensagem de falta de conexão (RNF24).

## Regras de negócio
- Validação de credenciais: e-mail normalizado + comparação de senha com hash bcrypt (UC005).
- A mensagem de erro **não revela** qual campo está errado (RNF11/RNF04 e Segurança).
- Token JWT com prazo de validade; sem refresh token no MVP (ver decisões). Após expirar, o usuário volta à tela 02.
- A resposta traz token + dados mínimos do usuário (id, nome, e-mail, Casa, papel).
